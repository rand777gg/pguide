# 02 · 编码规范

## 1. TypeScript

### 1.1 禁止 `any`

```ts
// ❌
function parse(data: any) { return data.list }

// ✅ 用 unknown + 类型守卫
function parse(data: unknown): Item[] {
  if (!isItemList(data)) throw new Error('响应结构不符合预期')
  return data
}
```

偶发场景确实绕不过去（比如对接没有类型的第三方库）时，用 `unknown` 加断言，
并写清楚为什么：

```ts
// 第三方 SDK 没提供类型定义，只能断言
const sdk = (window as unknown as { SomeSDK: SomeSDKLike }).SomeSDK
```

### 1.2 用 `type` 导入类型

开了 `verbatimModuleSyntax`，类型导入必须显式：

```ts
// ✅
import type { UserInfoVo } from '@pguide/shared'
import { ElMessage, type FormInstance } from 'element-plus'
```

原因是 `import { UserInfoVo }` 在编译后会产生真实的 import 语句，
而这个符号在运行时根本不存在，打包后可能直接报错。

### 1.3 联合类型优先于字符串

```ts
// ❌ 随手写字符串，拼错了要到运行时才发现
type ProjectLevel = string

// ✅
type ProjectTypeLevel = 'free' | 'unfree'
```

本项目里凡是取值来自后端字典的，一律用联合类型或常量对象，
并注明字典表位置。例子见 `packages/api/src/modules/mms.ts`。

### 1.4 不要用 `enum`

用 `as const` 对象：

```ts
// ❌ enum 会产生运行时代码，且和 isolatedModules 有摩擦
enum Status { Ok = 200 }

// ✅
export const HTTP_STATUS = {
  SUCCESS: 200,
  REDIRECT: 307,
} as const

export type HttpStatusCode = (typeof HTTP_STATUS)[keyof typeof HTTP_STATUS]
```

### 1.5 判等一律用 `===`

ESLint 里配了 `eqeqeq: ['error', 'always']`。
老代码里有 `if (res.code === 200 || res.code === 200)` 这种重复判断，
以及 `if (phone == null || phone == "")` 混用，都属于要避免的写法。

## 2. Vue 3

### 2.1 一律用 `<script setup lang="ts">`

不写 Options API，不写 `defineComponent` 包装。

```vue
<script setup lang="ts">
import { computed, ref } from 'vue'

const props = defineProps<{ project: ProjectCard }>()
const emit = defineEmits<{ (e: 'open', project: ProjectCard): void }>()

const title = computed(() => props.project.name)
</script>
```

### 2.2 props / emits 必须带类型

```ts
// ✅ 对象字面量形式，Vue 3.3+ 推荐
defineProps<{ tree: SubjectTreeNode[]; loading?: boolean }>()
defineEmits<{ (e: 'select', node: SubjectTreeNode): void }>()
```

### 2.3 组件名用多单词（PascalCase 文件名）

`InfoCard.vue`、`SubjectCascade.vue` ✅
`card.vue`、`item.vue` ❌

文件名和组件用途一致，**不要出现 `DetialSearchTitle.vue` 这种拼写错误**
（老工程里有，且该组件从未被使用）。

### 2.4 不要直接操作 DOM

```ts
// ❌ 老工程的写法：拼 style 字符串，拼错了也不报错
this.$refs.hrCard.style = "margin-left: 20px;z-index:1;background-color:write"

// ✅ 用响应式数据 + :style / :class
const offset = computed(() => index * 20)
```
```vue
<div :style="{ marginLeft: `${offset}px` }" :class="{ 'is-active': active }">
```

理由很直接：老工程里那个 `background-color: write` 就是这么混进去的。

### 2.5 v-for 必须带 key，且不要用 index

```vue
<!-- ❌ index 作 key，列表顺序变化时状态错乱 -->
<li v-for="(item, i) in list" :key="i">

<!-- ✅ -->
<li v-for="item in list" :key="item.subjectId">
```

### 2.6 路由守卫用返回值写法

```ts
// ❌ 老工程写法：next('/403') 之后又无条件 next()，重定向被作废
router.beforeEach((to, from, next) => {
  if (needLogin) next({ path: '/403' })
  next()   // ← 这一行把上面作废了
})

// ✅ Vue Router 4 返回值式：只走一条路
router.beforeEach(async (to) => {
  if (needLogin && !isAuthed) return { name: 'forbidden' }
  return true
})
```

## 3. 命名

| 对象 | 规范 | 例子 |
|---|---|---|
| 目录 | kebab-case | `user-center/`、`subject-cascade/` |
| Vue 组件文件 | PascalCase | `InfoCard.vue`、`UserCenterLayout.vue` |
| 普通 ts 文件 | kebab-case | `http-status.ts`、`storage-keys.ts` |
| 变量/函数 | camelCase | `subjectTree`、`loadSubjectTree` |
| 常量 | SCREAMING_SNAKE | `HTTP_STATUS`、`STORAGE_KEYS`、`MAX_PROJECT_NUM` |
| 类型/接口 | PascalCase，**不加 `I` 前缀** | `UserInfoVo`、`ApiResult` |
| 事件名 | kebab-case | `@select`、`@update:model-value` |
| CSS 类 | BEM + kebab | `.info-card__header`、`.nav-top__link` |

**布尔变量用 `is` / `has` / `can` 开头**：`isAuthenticated`、`hasToken`、`canSubmit`。

**不要用拼音，不要用单字母**（`r`、`v`、`t` 这类在老代码里到处都是，读起来很痛苦）：

```ts
// ❌
const r = await getSubjectTree()
this.allSearchBoxItems = r.data

// ✅
const adjacencyList = await subjectApi.fetchSubjectTree()
```

## 4. 注释

### 4.1 注释解释"为什么"，不解释"是什么"

```ts
// ❌ 废话
// 设置 token
setToken(value)

// ✅ 解释了非显然的约束
// 后端 RedisLoginCacheConstants.CAPTCHA_EXPIRATION 是分钟单位，
// 这里对齐成毫秒是因为前端要用来做倒计时
const CAPTCHA_TTL_MS = 60 * 1000
```

### 4.2 迁移/修复类改动必须写明原因

本项目保留了老工程，凡是**修正了老代码问题**的地方，都要写清楚
"老代码为什么是错的"，否则后人会以为是多余代码又改回去：

```ts
/**
 * 老工程 `request.js` 读 localStorage['token']，
 * 而 `utils/auth.js` 写的是 sessionStorage —— 两套存储不一致，
 * 导致登录状态随机失效。这里统一走 localStorage。
 */
```

// ❌ 说不清谁来管

// TODO(后端): 提供 GET /mms/project/type/dict 返回可用类型，前端不再硬编码

## 5. 错误处理

### 5.1 不要吞异常

```ts
// ❌ 出错了什么都看不到
try { await submit() } catch {}

// ✅
try {
  await submit()
} catch (error) {
  ElMessage.error(error instanceof ApiError ? error.message : '提交失败，请稍后重试')
}
```

### 5.2 API 错误必须用 `ApiError` 分流

`@pguide/api` 抛出的都是 `ApiError`，带 `code`：

```ts
import { ApiError } from '@pguide/api'

try {
  await mmsApi.checkProjectQuota()
} catch (error) {
  if (error instanceof ApiError && error.code === 500) {
    // 后端用 JsonResult.error('超过项目创建上限') 表示业务失败
    quotaReached.value = true
  }
}
```

不要用 `error.message.includes('上限')` 这种字符串匹配 —— 后端改文案就失效了。

### 5.3 `catch` 里变量类型是 `unknown`

`useUnknownInCatchVariables` 是打开的，取值前必须先收窄：

```ts
catch (error) {
  const msg = error instanceof Error ? error.message : String(error)
}
```

## 6. 禁止清单

| 禁止 | 替代方案 |
|---|---|
| `any` | `unknown` + 类型守卫 |
| `enum` | `as const` 对象 |
| 裸用 `localStorage` / `sessionStorage` | `@pguide/shared` 的 `readStorage` / `writeStorage` |
| 组件里 `import axios` | `@pguide/api` |
| 硬编码 `http://localhost:xxxx` | `import.meta.env.VITE_*` |
| 硬编码密码 / 密钥 | 环境变量，`.env*` 只提交模板 |
| `v-for` 用 index 当 key | 用业务 id |
| `@ts-ignore` | `@ts-expect-error` + 说明原因（前者会掩盖"其实已经不报错了"） |
| `console.log` 留在提交里 | `console.warn` / `console.error` 允许；调试用 `debugger` 或 vite devtools |
