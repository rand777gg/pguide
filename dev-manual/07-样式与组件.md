# 07 · 样式与组件

## 1. 样式一律 scoped

```vue
<!-- ✅ -->
<style scoped lang="scss">
.info-card { }
</style>

<!-- ❌ 会污染全局，老工程就是这么做然后出问题的 -->
<style lang="scss">
* { margin: 0; padding: 0 }
body { }
</style>
```

**老工程的实际故障**：`App.vue` 的**非 scoped** 样式里定义了
`* { margin: 0; padding: 0 }` 和 `#app { font-family: serif }`，
另外 `components/flips/BaseFlipTest.vue`、auth-ui 的 `waveInput.vue`
里也各有一段泄漏到全局的样式（后者甚至直接写了 `body {}`）。
样式来源无法追踪，改一处不知道会影响谁。

**全局样式只允许存在于 `src/styles/`**，由 `main.ts` 引入一次。

## 2. 设计令牌：不要写魔法值

所有颜色、间距、圆角、阴影都定义在 `src/styles/variables.scss`：

```scss
:root {
  --pg-color-primary: #409eff;
  --pg-spacing-md: 16px;
  --pg-border-radius: 8px;
  --pg-shadow-card: 0 2px 12px rgba(0, 0, 0, 0.06);
  // ...
}
```

```scss
// ✅
.info-card {
  padding: var(--pg-spacing-md);
  border-radius: var(--pg-border-radius);
  box-shadow: var(--pg-shadow-card);
}

// ❌ 数字和颜色散落各处，改主题要全局搜索替换
.info-card {
  padding: 16px;
  border-radius: 8px;
  box-shadow: 0 2px 12px rgba(0, 0, 0, 0.06);
}
```

**新增令牌时先加到 `variables.scss`，不要在组件里直接写值。**

## 3. CSS 类命名：BEM

```
块__元素--修饰符

.nav-top                 块
.nav-top__brand          元素
.nav-top__link           元素
.nav-top__link--active   修饰符（或用 .is-active）
```

配合 scoped 样式，用 `&__element` 嵌套：

```scss
.nav-top {
  &__inner { }
  &__brand { }
  &__link {
    &.is-active { }
  }
}
```

**不要用 `el-` 开头**（那是 Element Plus 的命名空间），
也不要用拼音、不要用 `.box1` `.box2` 这种。

老工程里 `document.querySelectorAll(".box")` 抓到了一堆无关元素 —— 
泛化类名 + 非 scoped 样式的组合，问题就是这样产生的。

## 4. 组件拆分标准

### 什么时候该拆

| 信号 | 说明 |
|---|---|
| 模板超过 ~120 行 | 难读 |
| 同一段模板出现两次 | 必然要抽 |
| 有独立的 props/emit 契约 | 天然是组件 |
| 需要单独测试 | 拆出来才能测 |

### 什么时候不该拆

只被一个页面用、没有复用价值、拆分后 props 反而变多 —— **别拆**。
过度拆分会让人在 8 个文件间跳来跳去才能看懂一个页面。

### 展示组件 vs 容器组件

```vue
<!-- 展示组件：只接收 props，只抛事件，不发请求 -->
<!-- components/InfoCard.vue -->
<script setup lang="ts">
defineProps<{ project: ProjectCard }>()
const emit = defineEmits<{ (e: 'open', project: ProjectCard): void }>()
</script>
```

```vue
<!-- 容器：负责取数、组合 -->
<!-- views/frame/HomeBody.vue -->
<script setup lang="ts">
import { loadHotProjects } from '@/services/project'
const projects = ref<ProjectCard[]>([])
onMounted(async () => { projects.value = await loadHotProjects() })
</script>
<template>
  <InfoCard v-for="p in projects" :key="p.id" :project="p" @open="openProject" />
</template>
```

**老工程的反例**：`components/card/InfoCard.vue` 的 `props` 是**空的**，
内容全是写死的（"项导--项目导航"、"名字长的大学"、"指导老师：xxx"），
还在 `mounted` 里用 `document.querySelectorAll(".box")` 全局初始化
vanilla-tilt。这样的"组件"没有任何复用价值。

## 5. Element Plus 使用约定

### 按需引入（已配置好）

`vite.config.ts` 里配了 `unplugin-vue-components` + `ElementPlusResolver`，
**直接用 `<el-xxx>` 即可，不需要 import**：

```vue
<template>
  <el-button type="primary">提交</el-button>
  <el-table :data="rows" />
</template>
```

以下情况需要显式 import：

**1. 函数式 API**（`ElMessage` / `ElMessageBox` / `ElNotification`）

```ts
// ✅ 什么都不用写，unplugin-auto-import 会按需注入
ElMessage.success('提交成功')
```

**2. 图标 —— 必须显式 import（这里踩过坑）**

```vue
<script setup lang="ts">
import { Search, ArrowRight } from '@element-plus/icons-vue'
</script>

<template>
  <el-icon><Search /></el-icon>
</template>
```

**`ElementPlusResolver` 只解析 `el-*` 组件，不解析图标。**
不显式引入的话，Vue 只会在控制台打印
`Failed to resolve component: Search`，页面上什么都不显示 ——
构建和类型检查都不会报错，属于容易漏掉的运行时问题。

> 为什么不用 `unplugin-icons` 的 `IconsResolver` 自动解析图标：
> 那需要额外引入 `@iconify-json/ep` 数据包。显式 import 只有一行，
> 而且能一眼看出这个组件用了哪些图标，更直观。

**3. 不要从 `element-plus` 根入口 import**

```ts
// ❌ 会把整个组件库拉进产物（实测 element-plus chunk 从 916KB 涨到 1MB+）
import { ElMessage } from 'element-plus'

// ✅ 什么都不写，交给 AutoImport
```

### 样式引入策略

`main.ts` 里全量引入了 `element-plus/dist/index.css`，
同时 `ElementPlusResolver` 的 `importStyle` 设为 `false`。

**为什么不全按需**：按需引入样式需要逐个组件 import，
一旦漏了某个（尤其是 `ElMessage` 这种函数式调用的）就会出现"组件没样式"，
排查成本高。全量 CSS 约 330KB，gzip 后 ~40KB，这个代价可以接受，
换来的是**不会出现样式缺失**。

组件 JS 仍然是按需的。实测数据（2026-09）：

| 项 | 体积 |
|---|---|
| 完整的 `element-plus/es` 包（磁盘） | 10365 KB |
| 完整的 `@element-plus/icons-vue` 包（磁盘） | 3218 KB |
| 本产物 `element-plus` chunk | **916 KB**（gzip 295 KB） |
| 本产物 `element-plus` CSS | 361 KB（gzip 48 KB） |

916KB 只占完整 es 包的 9%，说明按需引入**是生效的** ——
这个数字是用到的组件加上它们的共享依赖（`el-form` 的 async-validator、
`el-select` 的 popper / virtual-list 等）的真实成本。

**试过但无效的做法**：给 Rollup 加
`treeshake.moduleSideEffects` 把 `element-plus/es` 标成无副作用，
体积一个字节都没变（915.36KB 前后完全一致），所以没有保留这个配置。

**真要压体积，方向是减少组件使用**（比如用原生 `<select>` 替换 `el-select`），
而不是调 treeshake。

> 想改成完全按需样式：把 resolver 的 `importStyle` 改成 `'css'`，
> 并删掉 `main.ts` 里的全量 CSS 引入。做完要**逐页点一遍**确认没有样式缺失，
> 尤其是 `ElMessage` 这类函数式调用的组件。

## 6. 响应式

项目以桌面端为主（学生用电脑选项目、管理员用后台），
但首页在窄屏下要能看。

```scss
.home-body__grid {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(260px, 1fr));
  gap: var(--pg-spacing-md);
}
```

优先用 `grid` / `flex` 的自适应能力，**少写 media query**。
固定宽度（`width: 320px`）和绝对定位要谨慎 —— 老工程用 JS 改 `margin-left`
来排版卡片，窗口一缩放就错位。

## 7. 样式检查清单

- [ ] `<style>` 带 `scoped`
- [ ] 用 `var(--pg-*)` 而不是魔法值
- [ ] 类名是 BEM，不与 `el-` 前缀冲突
- [ ] 没有 `!important`（有的话说明选择器层级设计有问题）
- [ ] 没有在 JS 里拼 style 字符串
- [ ] 新增的设计令牌已加进 `variables.scss`
