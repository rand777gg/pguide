# 05 · 状态管理

## 1. 什么该进 store

判断标准：**这份数据是否被两个以上互不相关的页面/组件共享？**

| 该进 store | 不该进 store |
|---|---|
| 登录用户信息（`userInfo`） | 某个列表页的分页参数 |
| token | 表单的临时输入 |
| 全局主题 / 语言 | 弹窗开关 |
| 后端字典缓存（学科树等） | 只有单个组件用的 loading 状态 |

**局部状态留在组件里。** 老工程把 `userInfo` 塞进 Vuex 是对的，
但同时也塞了 `roles` / `permissions` / `name` 这些从没用过的字段，
还写了一个调用不存在函数的 `Login` action —— 这些都是噪音。

## 2. 用 Setup Store，不用 Options Store

```ts
// ✅ 本项目统一用 Setup Store（与 <script setup> 写法一致，TS 推导也更好）
export const useUserStore = defineStore('user', () => {
  const token = ref<string | null>(getToken())
  const isAuthenticated = computed(() => Boolean(token.value))

  function reset(): void {
    token.value = null
    clearToken()
  }

  return { token, isAuthenticated, reset }
})
```

```ts
// ❌ 不用 Options Store（state/getters/mutations/actions）
export const useUserStore = defineStore('user', {
  state: () => ({ token: null }),
  mutations: { SET_TOKEN(state, v) { state.token = v } },
})
```

Setup Store 的好处：不需要区分 getters/mutations/actions，
`computed` 就是 getter，函数就是 action，类型推导是原生的。

## 3. 命名与文件组织

- 文件：`src/stores/<域名>.ts`，一个 store 一个文件
- store id 与文件名一致：`stores/user.ts` → `defineStore('user', ...)`
- **目录名用 `stores`，不是 `store`**；**不是 `moudules`**
  （老工程是 `store/moudules/user.js`，两个拼写错误）

```
src/stores/
└── user.ts        useUserStore
```

## 4. 在组件里怎么用

```vue
<script setup lang="ts">
import { storeToRefs } from 'pinia'
import { useUserStore } from '@/stores/user'

const userStore = useUserStore()

// ✅ 需要响应式解构时用 storeToRefs
const { userInfo, loading } = storeToRefs(userStore)

// ✅ action 直接取，不需要 storeToRefs
const { logout } = userStore

// ❌ 直接解构会丢失响应性
const { userInfo } = userStore
</script>
```

## 5. 不要在 store 里 import 路由

```ts
// ❌ store 反过来依赖 router，会形成循环依赖，也没法单独测
import router from '@/router'
export const useUserStore = defineStore('user', () => {
  function logout() {
    reset()
    router.push('/')     // ← 副作用藏在 store 里
  }
})
```

正确做法：**store 只改状态，导航由调用方决定**

```ts
// store 里只做状态变更
function logout(): void { reset() }

// 组件里决定去哪
function handleLogout() {
  userStore.logout()
  router.push({ name: 'home' })
}
```

同理，`packages/api` 也不 import store —— 它通过 `onUnauthorized` 回调通知应用
（见 [04-API层与数据流](./04-API层与数据流.md) 第 6 节）。

## 6. 异步 action 要能表达失败

```ts
// ❌ 吞掉错误，调用方不知道成没成
async function loadUserInfo() {
  try {
    userInfo.value = await authApi.fetchUserInfoVo()
  } catch {}
}

// ✅ 返回结果 + 记录错误信息
async function loadUserInfo(): Promise<UserInfoVo | null> {
  loading.value = true
  try {
    const info = await authApi.fetchUserInfoVo()
    userInfo.value = info
    return info
  } catch (error) {
    lastError.value = error instanceof Error ? error.message : '获取用户信息失败'
    return null
  } finally {
    loading.value = false
  }
}
```

## 8. 后端字典数据的缓存策略

学科树（`/cms/subject/tree`）这类字典数据，多个页面都要用，
且变化极少。推荐做法：

- **现阶段**：不缓存，每个页面各自 `onMounted` 拉一次。
  数据量小（几十条），不值得引入缓存层。
- **将来变慢时**：再抽成 store 并加 `if (list.length) return` 的短路，
  或加 `loadedAt` 时间戳做 TTL。

**不要一开始就上缓存。** 先测出慢，再优化。

> 注意：后端 `ProjectDict` 是另一回事 —— 它在**服务端**用 `@PostConstruct`
> 把字典表全量加载进内存，前端不需要重复这件事。
